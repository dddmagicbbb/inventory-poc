# SSOT — 원본 문서 지정

> 작성일: 2026-11-24
> 이 문서는 **"무엇을 어디서 확인하는가"만** 정한다. 규칙의 내용은 각 원본에 있고, 여기에 다시 적지 않는다.

---

## 0. 원칙

1. **한 가지 사실은 한 곳에만 쓴다.** 그곳이 원본이다.
2. 원본이 아닌 문서는 원본을 **링크로 가리킨다.** 규칙을 다시 적어야 한다면 요약 한 줄 + 원본 링크로 끝낸다.
3. 문서끼리 내용이 다르면 [7절 충돌 정책](#7-충돌-정책)을 따른다.
4. 코드가 원본과 다르면 코드를 바로 고치지 않고 **GitHub Issue로 남긴다.**
5. 원본 변경은 [8절 보호 경계](#8-보호-경계)를 따른다. 사람의 요청으로 원본을 바꿀 때는 그 원본을 가리키는 파생 문서도 같은 작업에서 함께 맞춘다.

### 개별 작업 규칙
- 작업 하나 = Issue 하나. 브랜치·커밋·PR은 Issue 번호를 참조한다(`fix: … (#12)`).
- 작업 중 알게 된 **도메인·아키텍처 결정**은 Issue에만 남기지 않는다. 사람이 결정하고 반영을 요청하면 01 또는 06에 반영하고, Issue에는 그 링크를 남긴다.
- Issue가 닫히면 그 Issue는 기록이다. 이후 같은 사실의 기준은 01·06이다.

## 7. 충돌 정책

이 절에서 **SSOT**는 [1절](#1-원본-지정표)에서 지정한 도메인·아키텍처 원본(`01-requirements.md`, `06-architecture.md`)을, **참고 문서**는 [2절](#2-파생-문서-원본-아님)의 파생 문서를, **이슈**는 개별 작업의 GitHub Issue를 말한다.

| # | 충돌 | 처리 |
|---|---|---|
| 1 | 참고 문서 ↔ SSOT | **SSOT를 우선한다.** |
| 2 | 이슈 ↔ SSOT | **`NEEDS_HUMAN` 상태를 선언**하고 사람에게 판단을 요청한다. |
| 3 | SSOT ↔ SSOT | **`NEEDS_HUMAN` 상태를 선언**하고 사람에게 판단을 요청한다. |

### AI의 행동 제한
- 충돌이 발생하면 AI는 **자신의 판단대로 행동하지 않는다.**
- 1번은 정해진 규칙(SSOT 우선)을 적용하는 것이며, AI가 어느 쪽이 맞는지 판단하는 것이 아니다.
- 2번 · 3번은 어느 쪽을 따를지, 어느 문서를 고칠지 AI가 정하지 않는다. 사람의 결정이 나올 때까지 충돌과 관련된 작업은 진행하지 않는다.

### `NEEDS_HUMAN` 선언
충돌을 발견한 즉시 관련 작업을 멈추고 사람에게 아래를 알린다. 이슈가 있으면 그 이슈에도 같은 내용을 남긴다.

```
NEEDS_HUMAN
- 충돌 종류: 이슈 ↔ SSOT | SSOT ↔ SSOT
- 위치 A: <문서 · 절 또는 이슈 번호> — "<해당 내용>"
- 위치 B: <문서 · 절> — "<해당 내용>"
- 멈춘 작업: <진행하지 않은 부분>
```

사람이 결정하면 그 결정을 해당 SSOT(또는 이슈)에 반영한 뒤 작업을 이어간다.

## 8. 보호 경계

영역마다 읽기 권한과 변경 권한을 나눈다.

| 영역 | 해당 파일 | AI | 사람 |
|---|---|---|---|
| 애플리케이션 코드 | `src/` · `prisma/` · `scripts/` (검증 스크립트 제외) | Issue 범위 안에서 수정 | 최종 승인 |
| Issue별 테스트 | `tests/` | 작성 · 수정 | 전제 검토 |
| 요구사항 · 아키텍처 | `docs/01-requirements.md` · `docs/06-architecture.md` | 읽기 | 변경 · 승인 |
| 하네스 핵심 규칙 | `docs/harness/` · `AGENTS.md` · `CLAUDE.md` | 읽기 | 변경 · 승인 |
| 검증 스크립트 | `package.json` `scripts` 의 검증 단계 · `scripts/verify-*.ts` · `scripts/check-architecture.ts` · `.github/workflows/` ([`Verification.md`](Verification.md)) | 실행 | 정책 변경 승인 |

### 보호 영역 변경
- AI는 "읽기"·"실행"으로 지정된 영역을 **스스로 판단해 고치지 않는다.** 고쳐야 할 이유를 발견하면 사람에게 알리고 멈춘다.
- **사람이 보호 영역(SSOT 포함)의 수정을 요청하면 받아 준다.** AI는 요청받은 범위만 고치고, 변경한 파일과 내용을 사람에게 보고한다. 변경은 사람의 승인으로 확정된다.
- 요청 범위를 넘는 수정이 필요해 보이면 고치지 않고 먼저 묻는다.
- 수정 요청이 다른 SSOT와 충돌하면 [7절 충돌 정책](#7-충돌-정책)에 따라 `NEEDS_HUMAN`을 선언한다.
